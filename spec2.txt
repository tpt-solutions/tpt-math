# tpt-math Specification

## 1. Purpose
The numeric substrate for the TPT Solutions science / engineering / formal verification stack. `tpt-math` is a workspace of small, dependency-light, dual-licensed (`MIT OR Apache-2.0`) crates that wrap the best-of-breed pure-Rust math ecosystem (and, where no dual-licensed option exists, consolidate prior TPT crates) behind a coherent, `no_std`-friendly API.

## 2. Scope & Boundaries
- IN SCOPE: Pure mathematical primitives, numeric traits, linear algebra, probability, optimization, signal processing, graph theory, spatial kinematics, and interpolation.
- OUT OF SCOPE: Domain-specific physics solvers, CAD geometry, or engineering codes.
- DEPENDS ON: Minimal external dependencies (`uom`, `rustfft`, `rand`, `num-*`). All external deps must be dual-licensed per ADR-0007.

## 4. Build Order
1. `tpt-math-numeric` -> `tpt-math-linalg-dense` -> `tpt-math-linalg-fixed` -> `tpt-math-geometry` -> `tpt-math-spatial`
2. `tpt-math-units` -> `tpt-math-linalg` -> `tpt-math-linalg-complex`
3. `tpt-math-exact` -> `tpt-math-prob-*` -> `tpt-math-stats`
4. `tpt-math-graph`, `tpt-math-interpolate`
5. `tpt-math-autodiff-*`, `tpt-math-symbolic`, `tpt-math-optimize-*`, `tpt-math-signal-*`

## 5. Downstream Consumption
- `tpt-science`: `prob`, `stats`, `autodiff`, `optimize`, `signal`, `graph`.
- `tpt-engineering`: `linalg`, `units`, `optimize-convex`, `prob`, `spatial`.
- `tpt-fem`: `linalg`, `linalg-complex`, `optimize`.
- `tpt-physics`: `linalg`, `graph`, `spatial`, `interpolate`.
